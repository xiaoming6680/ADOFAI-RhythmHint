# 排键算法：数据来源和实现边界

当前基线为上游 `054fe9c` 的转角排键实现。排法有「标准」（时间重置法，默认）和「交替优先」（试验性）两种，见[排法说明](交替优先排法.md)；玩家自己做的手序见[专属手序](专属手序.md)。本文描述自动排键的数据来源和实现边界。

## 游戏数据到提示音符

`GameReader` 读取游戏已经算好的砖块时间、自动/中旋/假砖标志、长按、速度及转角，交给 `FloorHits.From`。起点不按；自动砖、中旋和假砖不产生独立击打；长按按住到下一块砖；下一块不是长按时是松开落上的尾巴，不另算按键；连续的长按砖每块都要重新按一下，各算一次。

`FloorHits.CheckAngles` 会分别核对砖块转角属于出发段还是到达段，用时长、速度和转角计算匹配比例。不够可信时退回未知角度；已知角度会累计跨过不需要按键的砖。这样得到的 `TileHit.Angle` 是从上一块要按的砖到这一块的转角，不能直接把原始方向值当作它。

`NotePlanner.Plan` 接收该击打序列。它不读取音乐文件，也不读玩家的专属手序；输出音符时间取合并组的首个击打，砖块范围记录首末边界。范围中可能包含被过滤的砖，不能用整数范围重造原始击打序列，所以交给编辑器的数据和专属手序文件都另存完整的 `hits`。

## 当前分组与排键

1. **已知转角的多押分组**：相邻击打的转角不超过 `ChordAngle`、间隔不超过 `ChordMaxGap` 时继续加入组，最多四个击打。默认分别是 30° 与 60 ms；角度比较有 0.1° 容差，用于游戏单精度误差。
2. **未知转角的回退分组**：仅在角度未知时使用 `ChordWindow`，按与组首击打的时间差判断，默认 35 ms。极快但转角正常的连打不能因时间很短就当多押。
3. **多押用手**：双押同手；三押是优先手两个键加另一手一个键；四押占用四轨。惯用手与多押用手是独立设置，后者可选另一只手。
4. **单押状态机**：以重置间隔 `R` 为界。均匀慢速单押倾向主手食指；`R/2 < 间隔 ≤ R` 倾向两手食指交替；更快时允许轮指。默认 `R=130 ms`，一半是 65 ms（2026-11-19 从 165 ms 改，见下一节）。
5. **让手与连按避让**：紧邻多押的单押可让给另一手；当前单押与紧邻上一音在 `JackWindow` 内同轨时尝试换轨。这些步骤可覆盖基础状态机。
6. **外轮与镜像**：外轮对符合条件的相邻同手音进行调整，尽量从外侧指到食指；惯用左手通过最终整体镜像得到。交替优先在同一管线中处理符合条件的单押片段，不重做多押分组。
7. **长按换手接**：上一音的长按到当前音还没松开（连续的长按砖）时，当前音换到另一只手；多押把按着的键当作不可用。外轮换手时也不换到接力那只手。2026-11-20 用户实测同一个键松开再按几乎按不了，见开发说明「排键规则」第 12 条。

## 6K、8K

6K、8K 有自己的排法（2026-11-22 用户：不照搬 4K，参考网上多键的手法另写；4K 不变）：慢的右手食指，中速左右食指轮流；快连打（R/2 以内）先在一只手上
从外往内滚到食指，这只手的手指都用过一遍还没完才换另一只手（2026-11-25 用户：轮指少换手、不跨中间；那只手刚按过、手指歇不够时才照原来的分法交给两只手），长串两只手整手轮流；多押手指够就放在一只手上。排完再顺一遍，同一根手指歇不到 R/2 又要按的换一根歇够了的
（同一只手相邻的优先，不造成孤立音符）。提示的个数和分组和 4K 一样。做法和约束见开发说明「排键规则」第 14 条。

参考的手法（冰与火和下落式音游玩家的说法，只取通用的）：多押、伪多押用同一只手；慢的用主手、中速两只手交替；四个键以上的快连打按固定方向滚（每只手先按的先松）；
多用一根手指，每根手指能慢一半；8K 是左右各 4 键。

这一关用几键默认按估算难度选（试验性），分界见验证记录。

## 主手重置间隔为什么是 130 ms

来由（2026-11-18）：玩家反馈手序不对，Avantgarde 用 R=165 时 75 ms 一块的转圈快段全排成 K J D F 轮指，没人这样打。用户给了该谱一个严判完美通关视频（B 站 BV1cN411V7Pb）让逐帧看手法。

做法：在浏览器里逐帧读视频左下角的按键显示（11 个键框，按下时整格变亮），去掉整屏闪白的帧，和游戏导出的这一关砖块时间对齐（时间差 0.708 秒），968 个音里读出 889 个的按键。玩家整首只用两个键（右手主键、左手副键），没有轮指。按和上一下的间隔统计换不换键：

| 间隔 | 同一个键 | 换键 |
|---|---|---|
| 75 ms | 0 | 408 |
| 100 ms | 0 | 21 |
| 150 ms | 308 | 4 |
| 225 ms | 6 | 24 |
| 300 ms | 53 | 2 |
| 400 ms 以上 | 41 | 1（42 次停顿后 41 次从主键起手） |

先照这个视频做过一个只用两根食指、按拍点奇偶换手的排法（「拍点交替」，和视频 98% 一致），但用户在 deleted（工坊 3386617648）上试了说不行：那张谱 50 ms 一下的旋转短串（4–8 个音）必须轮指，两指交替每根手指 100 ms 就得按一下。2026-11-19 删掉了这个排法，改成只调标准排法的 R：

| R（轮指线 R/2） | Avantgarde 和视频一致 | deleted 50 ms 短串 |
|---|---|---|
| 165 ms（82.5 ms，原默认） | 388/889 = 43.6% | 照常轮指 |
| **130 ms（65 ms，现默认）** | **768/889 = 86.4%** | **照常轮指（和原来完全一样）** |
| 165 ms、关掉轮指 | 440/889 = 49.5% | 不轮指 |

R=130：75 ms 两指交替、150 ms 单指连点（视频都是这样）、50 ms 轮指。视频里剩下没对上的主要是 225 / 300 ms 那种「隔奇数个单位换手」，标准排法只看间隔、不看拍点，做不到；这部分没有再加规则。

本机 20 张工坊关卡（31451 个音，`tools/Preview.cs --reset 165` 对比默认）：外侧键占比 32.5% → 29.9%，跳轨 30.3% → 27.4%，主手重置间隔以内同手相邻（轮指）7811 → 6902，孤立音符都是 0，多押分组和用手不变。大多数轮指保留，只有 65–82.5 ms 那一档改成交替。

老设置文件里重置间隔还是 165 的，第一次加载时改成 130（`Settings.MigrateDefaults`），玩家自己调过的不动。交替优先的短串上限同样受 R/2 约束，默认下变成 60–65 ms。

离线复现某个排键结果需要全部参数和所选排法，包括 `ChordAngle`、`ChordMaxGap`、`ChordsOnOtherHand` 和交替优先的短串参数；只记旧版七个时间参数不足以重建当前结果。

## 不应扩大理解的保证

- 「相邻连按」指相邻提示之间共享轨道，不覆盖中间隔了其他音符的所有重复用指。
- 外轮、让手和片段衔接会影响局部手序；相同局部间隔不代表不同前后文必定产生相同形状。
- 长按时长保留，不等于已经实现完整的长按占手优化。交替优先在含长按的谱面上整体沿用标准排法。
- 随机与边界测试是覆盖证据，不是对所有参数组合与关卡的数学证明。游戏实际手感仍需玩家验证。

## 离线实现与自动对照

C# 离线读谱现在有两份，用途不同（要不要合成一份以后再定）。两份都把算出的砖块交给同一份 `FloorHits` 筛选击打、核对与累计转角，也都能修几种老谱的 JSON 写法：

- **严格**：`tools/Preview.cs` 的 `AdofaiTiming`。离线预览、给排键试验台导出（`--export`）、给编辑器写会话（`--editor-session`）都用它。只算 SetSpeed、Twirl、Pause（含游戏对 9–16 版暂停的迁移）和中旋，支持 angleData 和 pathData（绝对方向、5 版以后的相对方向）；遇到其他影响时间或按键的事件（Hold、AutoPlayTiles 等）、非零 angleOffset、带 duration 或 eventTag 的时序事件（Pause 的 duration 除外），直接报错退出，提示去游戏里导出。保留上游的 pathData、Pause 和出发间隔算法。
- **宽松**：`src/RhythmHint.Reference/AdofaiLevelReader.cs`。难度校准（`tools/Difficulty.cs`）、`DifficultyTests`、`BeatGridTests.RealCharts` 这类要成批读外部谱面、允许个别不准的地方用。比严格的那份多算 Hold 和 AutoPlayTiles；影响时间但没算的（多星球、自由区、带 angleOffset 的变速、angleData 里的 null 等）不报错，记进 `Unsupported`，由调用方决定要不要这一关（见[难度估算](难度估算.md)）。

JavaScript 导入器（`tools/planner-js/adofai-import.js`）照严格的那份实现相同的有限离线流程；JavaScript 排键实现则通过 C# 生成的合成基线对照当前 `NotePlanner`。自动测试覆盖带角度/未知角度、双押/三押/四押、两种排法、参数变化和镜像；Preview CLI 整谱对照另外核对双方支持的时间事件、pathData、转角和排键结果。

严格的离线读取器（`AdofaiTiming` 和 JS 导入器）明确拒绝未支持的时间或输入事件，不能静默略过后把结果标作真实游戏谱面；宽松的 `AdofaiLevelReader` 不拒绝，但把没算的事件写进 `Unsupported`，用的地方要自己看。即使 JS 和 C# 完全一致，也只说明两份离线实现一致；游戏倒计时、校准和完整事件系统不在这一保证内。需要准确时序时以游戏里的数据为准（「编辑本关手序」交给编辑器的就是游戏数据）。

## 历史证据的适用范围

PR #1 基于纯时间判双押版本及不含转角的个人审核文件提出过偏好候选（即现在的交替优先）。那些命中统计不用于验证当前转角判多押算法，也没有据此修改默认排法。以后评估排法，用带转角的游戏数据先精确复现原排法，再看玩家在专属手序里改了哪里、没改的地方又被动了多少。
